## Реализовано в текущей итерации

- Добавлены два явных режима аккаунтов. Личный мастер по умолчанию использует независимый:
  каждый аккаунт ведёт отдельный цикл в каждом чате. Сохранённые старые сценарии продолжают
  использовать распределение и не меняют объём задним числом.
- Планировщик разворачивает матрицу «аккаунт × чат», сохраняет одиночный sender pool каждой
  независимой задачи и продолжает следующий цикл тем же аккаунтом.
- Для каждой пары сохраняются измеренная активность, сглаженный интервал и класс
  `turbo/fast/steady/quiet`; Telegram slow mode и ручные ограничения остаются приоритетными.
- Preflight независимой кампании требует готовности всех пар. Отказ, таймер или бан одного
  аккаунта не отменяет и не переносит потоки остальных.
- Карточка запуска показывает число потоков, статистику по аккаунтам/чатам и обученную
  авточастоту каждой пары.
- Отчёт запуска перестроен как операторская сводка: явный статус, ближайшая отправка, шкала
  покрытия, проблемные чаты первыми, статистика каждого аккаунта и сохранённые сбои попыток.
- Длинные разделы отчёта ограничиваются безопасно до лимита Telegram; из карточки доступны
  обновление, остановка, редактирование активного запуска и переход к исходному сценарию.
- Worker обрабатывает разные аккаунты параллельно, но атомарно не берёт две публикации одного
  аккаунта одновременно; стандартная параллельность личного контура увеличена до четырёх.
- Первый замер активного профиля выполняется через минуту, жёсткий дедлайн не перескакивается,
  а публикации остальных управляемых аккаунтов вычитаются из органической активности чата.

- Модель и миграция сохранённой preflight-карты «аккаунт × чат».
- Live-проверка членства, права писать и slow mode без вступления и отправки.
- Сервис кампаний для построения и сохранения карты готовности.
- Кнопка `🩺 Проверить готовность` и сводка покрытия в Telegram-боте.
- Выбор отправителя учитывает известное членство и блокировки.
- Следующий цикл сохраняет закреплённого за чатом отправителя; резерв используется при проблеме.
- Добавлен виртуальный план мощности по pace, суточному лимиту и микропаузам, чтобы задачи
  не создавались все одновременно готовыми.
- Добавлен расчёт реальной суточной мощности и процента выполнимости выбранной частоты.
- Activity-aware расписание полностью подключено: позиция своего поста сохраняется, а повтор
  ждёт заданное число новых сообщений либо максимальный срок ожидания.
- Активная видимость настроена на 10 новых сообщений с проверкой каждую минуту и жёстким
  дедлайном 15 минут; повтор допускается по первому наступившему условию, а первый замер также
  происходит через минуту.
- Рекламный пост сохраняет Telegram HTML-форматирование и может содержать фото, видео или
  документ с подписью; файл и форматирование фиксируются снимком активного запуска.
- Медиа хранится только внутри настроенного каталога, проверяется по размеру и типу.
- Добавлены три готовых профиля: активный, средний и бережный. Один клик согласованно меняет
  срок, базовый интервал, глубину видимости, частоту проверки и максимальное ожидание.
- Все параметры профиля доступны для независимой ручной настройки в черновике и сохранённом
  сценарии, включая выключение адаптивности и автозамены.
- Рассылка поддерживает до 10 включаемых вариантов поста с круговой ротацией отдельно для
  каждого чата; вариант можно создавать, переименовывать, редактировать и удалять.
- Каждый вариант поддерживает одиночный файл или альбом до 10 фото/видео. В очередь сохраняется
  неизменяемый снимок выбранного варианта и полного набора медиа.
- В боте добавлен точный личный предпросмотр без публикации в аудитории и статистика доставки
  по вариантам в карточке запуска.
- Перед LIVE-запуском обязательна свежая preflight-карта членства и права писать; для диалога
  проверяется каждый аккаунт цепочки, для независимой рассылки — каждая пара аккаунт × чат,
  для распределённой — хотя бы один выбранный отправитель на чат.
- Добавлен API `POST /api/v1/campaigns/{id}/preflight` и время последней проверки в отчёте.
- Все операции одного аккаунта переведены на общий Telethon-клиент и общий lock; конкурентные
  соединения с одним `auth_key` исключены.
- `tdata` создаёт отдельную серверную сессию с собственным API ID через зарезервированный прокси;
  ключ Telegram Desktop не сохраняется.
- Альбомы используют обязательный `messages.uploadMedia`, preflight проверяет права каждого типа
  контента, `FLOOD_WAIT` не обрезается, лимит `vCard` считается в UTF-8 байтах.
- Личная база обновлена до миграции `0030_independent_adaptive_streams`; перед миграцией создана
  консистентная копия `backups/proxima-20260802T161641Z.db`. Doctor после обновления: integrity
  `ok`, нарушений внешних ключей `0`, отсутствующих таблиц и колонок `0`.

## Продолжить отсюда

Основной личный контур независимых активных рассылок, молодых display names, нативных контактов и
защит Telegram RPC готов. Следующий обязательный шаг перед фактическим LIVE — операторский прогон
на выделенных тестовых аккаунтах/чатах и проверка инфраструктуры Linux/proxy; диалоги не изменялись.
