# План реализации

## Текущий этап — Control Bot и надёжное ядро

- [x] Базовые модели аккаунта, цели, кампании, запуска и действий.
- [x] Dry-run шлюз с точным `reply_to_message_id`.
- [x] Идемпотентный `request_key`.
- [x] Очередь с двумя сохранёнными шагами.
- [x] Lease, повтор, отмена и восстановление протухших задач.
- [x] Начальная миграция Alembic.
- [x] Исправить тесты после перехода с синхронного запуска на очередь.
- [x] Закрытый aiogram-бот.
- [x] Главное inline-меню с редактированием одного сообщения.
- [x] FSM добавления аккаунта, цели, шаблона и кампании.
- [x] Экраны запусков и аудита.

## Этап 2 — Контент и базы целей

- [x] Таблица и мастер создания шаблонов.
- [x] Именованные базы целей.
- [x] Загрузка `.txt` через бота с валидацией и отчётом.
- [x] Вставка списка сообщением, нормализация Telegram-ссылок и дедупликация.
- [x] Распознавание общих папок `t.me/addlist/...` без ложной попытки раскрыть их через Bot API.
- [x] Снимок шаблона и базы в момент запуска.
- [x] Пакетное создание задач без дублей.

## Этап 6 — Загрузка аккаунтов и live-отправка

- [x] Импорт `tdata` (`.zip`) через бота в отдельный `StringSession` с собственным API ID:
  ключ Desktop используется только для подтверждения и не сохраняется, соединение идёт через
  заранее зарезервированный прокси.
- [x] Импорт `.session` и строки `StringSession` (Telethon) с API-кредами из настроек.
- [x] `cryptg`-шим вместо C-расширения `tgcrypto` (без компилятора).
- [x] Шифрование сессий (`PROXIMA_ACCOUNT_ENCRYPTION_KEY` с fallback).
- [x] Модель/миграция: источник сессии, зашифрованная сессия, API-креды, телефон, username.
- [x] Карточка аккаунта: проверка живости сессии, привязка/снятие прокси, пауза, удаление.
- [x] `TelethonGateway`: live-отправка с маршрутом `account:<id>` и классификацией ошибок Telegram.
- [x] Переключаемый `dry-run` / `live` шлюз (`PROXIMA_DRY_RUN`).
- [x] Тесты round-trip импорта tdata, шифрования, жизненного цикла и требований API.
- [ ] Опциональный системный egress kill switch для полной гарантии отсутствия утечки IP.

## Этап 3 — Пул прокси

- [x] Зашифрованное хранение паролей прокси.
- [x] Одиночное добавление и массовый TXT-импорт через бота.
- [x] HTTP, HTTPS, SOCKS5/SOCKS5H и распространённые компактные форматы.
- [x] Группы, фильтры, метки и перенос между группами.
- [x] Точечная и параллельная массовая проверка, latency и внешний IP.
- [x] Счётчики успешных/неуспешных проверок и автоматический карантин.
- [x] Ручное резервирование под именованный слот и автоназначение лучшего свободного прокси.
- [x] Замена адреса/пароля, включение, пауза, освобождение и безопасное удаление.
- [x] Полный backend API без выдачи паролей наружу.
- [x] Миграция, аудит и тесты жизненного цикла прокси.
- [x] Fail-closed resolver маршрута `account:<id>` без прямого fallback и с remote DNS для SOCKS5.
- [x] Подключить fail-closed resolver к live gateway и сбрасывать клиент при смене маршрута/IP.
- [ ] Добавить системный egress kill switch и интеграционные тесты утечки IP/DNS/IPv6.

## Этап 3.1 — Разрешение целей пользовательским коннектором

- [x] Безопасно распознавать публичные, приватные и folder-ссылки на уровне импорта.
- [x] Показывать превью общей папки через `chatlists.checkChatlistInvite`.
- [x] Импортировать только доступные группы без автоматического вступления во время импорта.
- [x] Сохранять peer ID и проверять доступ/право отправки перед live-отправкой.

## Этап 3.2 — Умная рассылка и отчёты

- [x] Конечные серии до 100 проходов с отдельным номером цикла у каждой задачи.
- [x] Закрепление одного отправителя за чатом на всю серию.
- [x] Предварительная проверка Telegram slow mode и точного `next_send_date`.
- [x] Персистентный таймер пары «аккаунт + чат» без расходования попыток.
- [x] Ручной минимальный интервал чата и быстрые пресеты в боте.
- [x] Редактирование цели и расписания сценария без потери старой истории.
- [x] Отчёт со ссылками на сообщения, ближайшей очередью и номером прохода.
- [x] Остановка всей серии и повтор только ошибочных задач.
- [x] Непрерывный режим на 1–168 часов с одной следующей задачей на каждый чат.
- [x] Точный приоритет таймера чата и настраиваемый интервал для чатов без таймера.
- [x] Снимки срока, интервала, текста, пула аккаунтов и автозамены на уровне запуска.
- [x] Автозамена недоступного отправителя только внутри выбранного пула с полным аудитом.
- [x] Живой отчёт по чатам, аккаунтам, реальным публикациям, очереди и заменам.
- [x] Подавление шумных уведомлений об успешном промежуточном посте умной рассылки.
- [x] Activity-aware повтор по глубине новых сообщений с максимальным ожиданием.
- [x] Виртуальное планирование мощности аккаунтов до создания задач.
- [x] Форматированный рекламный пост с фото, видео или документом и снимком запуска.
- [x] Preflight-карта членства/права писать и обязательная свежесть перед LIVE-запуском.
- [x] Готовые профили активной, средней и бережной рассылки для черновиков и сценариев.
- [x] Быстрый адаптивный профиль: 10 сообщений или дедлайн 15 минут с минутной проверкой.
- [x] Независимая ручная настройка всех параметров частоты в черновике и сценарии.
- [x] Круговая ротация до 10 вариантов рекламного поста со снимком на уровне задачи.
- [x] Альбомы до 10 фото/видео, одиночные документы и личный предпросмотр администратора.
- [x] Telegram-совместимая загрузка каждого элемента альбома через `messages.uploadMedia` до
  `messages.sendMultiMedia`, без приватного `_file_to_media`.
- [x] Отчёт доставки по вариантам контента.
- [x] Независимая матрица потоков «каждый выбранный аккаунт × каждый чат» без взаимной остановки.
- [x] Снимок режима аккаунтов и одиночный пул отправителя внутри независимой задачи.
- [x] Обучаемый интервал, скорость сообщений и класс частоты отдельно для каждой пары.
- [x] Строгий preflight всех пар в независимом режиме и обратная совместимость распределения.
- [x] Content-aware preflight прав на фото, видео, документы и нативные контакты.
- [x] Единый Telethon-клиент/lock аккаунта для отправки, проверки, профиля, аватара и папок.
- [x] Полное соблюдение серверного `FLOOD_WAIT` без сокращения локальным лимитом.
- [x] Отчёт по потокам: аккаунт, чат, класс скорости, интервал, активность и следующее разрешение.
- [x] Операторский статус запуска, шкала покрытия и сортировка проблемных чатов/аккаунтов первыми.
- [x] История сбоев отдельных попыток, даже если последующий повтор завершился успешно.
- [x] Гарантированный лимит карточки отчёта и быстрый переход к исходному сценарию.
- [x] Параллельная обработка разных аккаунтов без одновременного залпа одним аккаунтом.
- [x] Минутный первый замер активного профиля и исключение собственных управляемых публикаций
  из оценки органической активности.
