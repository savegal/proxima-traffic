# Проверка замечаний к Proxima Traffic — 25.10.2026

Проверены текущий код, реальные фильтры и middleware aiogram, запросы SQLite и обработчики. Проверки работают с отдельными тестовыми базами и подставными Telegram-клиентами.

## Результаты по пунктам

| Пункт | Результат проверки | Исправление или доказательство |
| --- | --- | --- |
| 1.1. Двойное сохранение / сохранение одновременно с запуском | В штатном dispatcher не воспроизводится. | `ControlEventIsolation` уже сериализует события одного оператора до чтения состояния и выбора обработчика. После первого подтверждения второй callback не проходит фильтр состояния. Проверены save/save, save/launch, launch/save, pr:create/create и pr:save/save через настоящий dispatcher. Дополнительные блокировки не добавлялись. |
| 1.2. Медиа отменённых и перезаписанных черновиков | Подтверждено. Существовал ручной GC, но немедленной очистки не было. | Добавлена очистка после удаления ссылок из FSM. Она сохраняет медиа кампаний, снимков запусков, правил, историй и других сохранённых черновиков. Проверка ссылок и удаление выполняются при блокировке записи SQLite. При недоступной БД файл остаётся на диске. Пути вне медиакаталога не удаляются. |
| 1.3. Пустая или повреждённая цепочка в настройках реакций | Причина уточнена: `validate_dialogue_steps` не возвращает пустой список, а выбрасывает `ValueError`. Экран действительно переставал открываться. | Карточки показывают повреждение и сохраняют доступ к восстановлению/удалению. Пустой JSON, неправильная форма JSON и некорректный номер шага больше не приводят к падению или молчаливому выбору другого автора. |
| 1.4. Отрицательное число ошибок ЛС | Подтверждена гонка, но не предложенная причина с `CANCELLED`. | `uncertain` уже ограничен статусом `FAILED`. Однако общий счётчик и неопределённые исходы читались разными запросами. Воспроизведён переход RUNNING → FAILED между чтениями: failed=0, uncertain=1. Теперь связанные значения вычисляются одним запросом; дополнительно ограничен снизу вывод на четырёх экранах. |
| 2.1. Потеря traceback | Подтверждено. | Обычные `ValueError`, `KeyError` и `IndexError` логируются как внутренние ошибки с исходным traceback. Оператор получает безопасный текст без внутренних деталей. Известные доменные ошибки сохраняют краткую обработку. |
| 2.2. Кнопка изменения задержки в MESSAGE_EDIT | Не подтверждено. | `edit_channel_comment_review` уже выбирает `message_edit_delay` для этого режима и показывает соответствующий запрос. Добавлена проверка маршрута. |
| 2.3. Повторное оформление клавиатуры | Подтверждена лишняя обёртка; дублирования кнопок она не создавала, поскольку оформление идемпотентно. | Удалён отдельный декоратор у `direct_service_action_menu`; оформление выполняет общий цикл. |
| 2.4. Обрезка составных эмодзи | Подтверждено для ZWJ, модификаторов и других составных последовательностей. | UTF-16-лимит сохранён; граница отступает к началу разрезанной последовательности. Проверены семейный эмодзи, тон кожи, флаг, вариационный селектор, комбинируемый акцент и keycap. Исходное `errors="ignore"` не оставляло половину суррогатной пары, но не защищало составной эмодзи. |
| 2.5. Названия недоступных аккаунтов | Подтверждено. | Для карточек используются ID привязанных аккаунтов и `account_labels_by_ids`, включая приостановленные и разлогиненные аккаунты. Фильтр готовности остаётся только в выборе новых исполнителей. |
| 3. Ошибки ввода отдельными сообщениями | Подтверждено. | 132 ответа валидации в 68 обработчиках переведены на `answer_panel_input`: ошибка меняет панель, сохраняет ввод и кнопку отмены. Отдельные уведомления после долгой операции, когда уже открыт другой черновик, этим преобразованием не затронуты. |
| 3. Поздняя проверка доступа | Подтверждена лишняя работа FSM для посторонних обновлений. | Проверка администратора перенесена на уровень Update после штатного UserContext и перед таймингом/FSM. Для неавторизованного сообщения и callback проверено отсутствие чтений состояния и создания блокировок FSM. Ограничение управления личным чатом сохранено. |
| 3. Отсутствие `render_as_batch` | Улучшение генерации миграций, а не поломка уже написанных миграций. | Включён для SQLite в online/offline-конфигурации. Тест создаёт миграцию через autogenerate во временной копии проекта, проверяет batch-блок и действительно выполняет удаление колонки. Существующие миграции не переписывались; новая ревизия схемы не требуется. |
| 3. Ошибка экрана после потребления черновика имён | Подтверждено. | Прогресс показывается через общий защищённый редактор. Ошибка Telegram при подтверждении/обновлении прогресса логируется и не отменяет уже подтверждённое применение имён. Повторное подтверждение по-прежнему не выполняет операцию второй раз. |

## Проверки

- Воспроизведение гонки счётчиков выполняется с настоящей SQLite: отдельный писатель завершает задание между запросами чтения. Проверены дашборд и карточка запуска.
- Отдельно проверено, что `CANCELLED/cancelled_outcome_unknown` не вычитается из числа `FAILED`.
- Очистка проверена для отмены, перезаписи, сохранения кампании, ссылки из другого сохранённого FSM-черновика, ошибки БД и файла вне медиакаталога.
- Проверены исходные traceback и отсутствие внутренних подробностей в сообщении оператору.
- В целевых и смежных наборах совокупно проверено **607 разных успешных тестов**, **2 неприменимых параметризованных варианта пропущены**. Повторные прогоны в сумму повторно не входят.
- Ruff проверенных модулей и новых строк в крупных общих модулях; проверка неопределённых имён; `compileall` — успешно.

Тестовые заглушки FSM в трёх существующих файлах дополнены методом `get_state`, который использует общий редактор панели. Поведение приложения ради неполных заглушек не ослаблялось.
